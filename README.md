# 온곁 · 6학년 인구교육 프로젝트 스케줄러

웹앱: https://baekdong-population-2026.web.app

React + Vite, Firebase Authentication(Google), Firestore(서울), Firebase Hosting으로 구현했습니다.

## 선생님이 사용하는 방법

1. 첫 화면에 **2026. 인구교육 프로젝트 6학년**과 전체 수업 계획표가 바로 표시됩니다. 조회와 자료 다운로드는 누구나 가능합니다.
2. 오른쪽 위 **Google 로그인**을 누르면 일정·진행 체크·논의사항을 편집할 수 있습니다. 별도의 교사 등록은 필요하지 않습니다.
3. 관리자는 `kth9302@gmail.com`입니다. 관리자만 반 이름·담당 선생님·패들렛 주소와 자료 업로드·삭제를 관리합니다.
4. **반별 달력**에서 반과 차시를 선택해 일정·준비사항을 등록합니다. 같은 일정을 여러 반에 등록할 수 있고 같은 반의 시간 중복을 확인합니다.
5. **진행 체크**에서 활동 완료·패들렛 업로드·활동지 작성을 독립적으로 체크합니다. 반 이름을 바꾸어도 기록은 유지됩니다.
6. **논의사항**에서 논의 내용, 담당, 목표일, 합의·실행 결과를 함께 정리합니다.
7. **수업 자료실**에서 PPT와 활동지를 다운로드합니다. 관리자는 파일 또는 공유 링크를 등록하고 프로젝트·차시에 연결할 수 있습니다.

공개되는 데이터는 수업 계획, 일정, 진행 체크, 논의사항, 자료실입니다. 관리자·교사 계정 등록 목록은 공개되지 않습니다. 편집자 기록은 이메일 대신 Firebase 사용자 ID로 저장합니다. 날짜는 한국 시간 기준입니다.

화면은 제공된 계획표의 연보라색 칸·분홍색 구분선·병합 표 구조를 살렸고, 역량·교육공동체 아이콘은 한글 원본에서 추출했습니다. 스마트폰에서는 표 영역을 좌우로 움직여 볼 수 있습니다.

## 프로젝트 순서와 한글 파일

| 프로젝트 | 내용 | 전체 차시 |
| --- | --- | --- |
| 1 | 우리는 모두 소중해요 | 1~10 |
| 2 | 인구교육 굿즈, 마을과 함께 나눠요! | 11~20 |
| 3 | 내일의 인구, 우리가 디자인해요! | 21~30 |

원본 `_수정전.hwpx`를 보존하고 `_순서수정.hwpx`를 별도로 생성했습니다. 단순한 숫자 치환이 아니라 제목·지도안 표를 묶어서 순서도 옮겼습니다. 프로젝트 번호 그림도 교환했습니다. 27개 지도안 묶음, 총 30차시가 유지되며 묶음 3~4, 24~25, 28~29차시를 각각 체크할 수 있습니다.

변경 내역은 `차시_변경내역.txt`에 있습니다. XML과 ZIP 구조, 차시와 프로젝트 이미지 참조를 검증했습니다. 한글 앱에서 출력 레이아웃을 직접 렌더링한 검증은 수행하지 않았습니다.

스케줄러 차시 제목은 최신 계획표를 기준으로 합니다. 계획표의 21차시 ‘우리학교의 변화’와 상세지도안의 ‘우리나라의 인구 변화’는 표현이 다르므로 수업 상세 화면에 안내했습니다. 상세 지도안의 활동 내용과 목표는 순서 변경 외에 보존했습니다. 계획표에 적힌 공개수업 후보는 26, 30차시에 표시합니다. 정책 수업은 제공된 자료에 따라 ‘정책 홍보와 지원 방안 토의’ 내용입니다.

## 나중에 PPT와 활동지를 추가하기

### 폴더에서 추가

`추가자료` 폴더에 파일을 넣고 다음 명령으로 빌드·배포합니다.

```powershell
npm run deploy
```

파일명 `P2_11차시_인터뷰_활동지.hwpx`처럼 차시를 넣으면 자료실과 그 차시 상세 화면에 자동으로 연결됩니다. `P2_굿즈제작_참고자료.pdf`는 프로젝트 2 전체 자료로 연결됩니다. 차시가 있으면 프로젝트는 전체 차시 번호로 판단합니다. 지원 형식은 HWP/HWPX, PPT/PPTX, PDF, DOC/DOCX, XLS/XLSX, ZIP, PNG/JPG/JPEG/WebP입니다. 폴더에서 제공하는 파일은 배포된 정적 파일이므로 주소를 아는 사람도 다운로드할 수 있습니다.

### 공유 링크로 추가

관리자가 **자료 등록 → 공유 링크**를 선택해 Google Drive 등의 링크를 등록할 수 있습니다. 링크 대상의 열람 권한은 해당 서비스에서 설정합니다.

### 웹앱 파일 업로드

Dream 결제 계정에 연결된 Blaze 요금제와 서울 리전 Storage 버킷이 활성화되었습니다. 관리자는 **자료 등록 → 파일 업로드**에서 최대 50MB 파일을 올릴 수 있습니다. 로그인하지 않은 방문자도 자료실에 등록된 파일을 내려받을 수 있습니다.

Storage 보안 규칙은 검증된 관리자 Google 계정을 직접 확인합니다. Firestore 조회용 프로젝트 IAM 권한은 추가하지 않았습니다. 다운로드 CORS 출처는 이 웹앱의 `web.app`, `firebaseapp.com` 및 로컬 개발 주소입니다. 관리자 이메일을 바꿀 때는 Firestore 관리자 등록과 `storage.rules`의 계정 조건을 함께 수정해야 합니다.

## 개발과 확인

```powershell
npm install
npm run dev
npm test
npm run build
firebase deploy --only 'firestore,hosting'
```

한글 자료를 다시 반영하려면 lxml이 설치된 Python으로 `scripts/prepare_curriculum.py`를 실행합니다. 원본과 계획표가 현재 폴더에 있어야 합니다.

`node scripts/check-rules.cjs`는 로그인된 Firebase CLI의 인증을 사용해 Firebase 공식 Rules 테스트 API로 공개 조회, Google 로그인 편집, 관리자 업로드 접근 제어를 읽기 전용으로 검증합니다. 운영 데이터에 테스트 문서를 쓰지 않습니다. `scripts/cloud-admin.cjs status`는 인증과 결제 상태를 확인합니다. 클라이언트 Firebase 설정값은 공개 식별자이며 접근 제어는 Google 인증과 관리자 보안 규칙으로 적용합니다.

검증: 전체 차시 정렬·그룹 유지, 반별 독립 체크 집계, 일정 겹침, 링크 검증 단위 테스트; 브라우저에서 두 반 일정 등록, 독립 완료 체크, 논의 저장, 새로고침 보존, 데스크톱·모바일 화면 확인; Firebase Rules 24개 접근 제어 테스트 및 배포 시 규칙 컴파일 확인; 운영 주소의 자료 다운로드 파일 일치 검증; 원본 자료 대신 빈 ZIP 검증 파일을 이용한 Storage 공개 다운로드·CORS 검증 및 임시 파일 정리. 사용자 Google 계정으로 실제 로그인한 두 기기 사이의 공유 검증은 별도 수행하지 않았습니다.
