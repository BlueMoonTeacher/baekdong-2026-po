## 남은 진도 자동 배정

첫 화면의 **남은 진도 자동 배정**, 또는 **반별 달력 → 진도 자동 배정**을 사용합니다. Google 로그인 후 미리보고 저장하면 반별 달력에 반영됩니다.

- 반을 하나 또는 여러 개 선택하고, 시작일과 주로 수업하는 요일을 지정합니다. 기본값은 **화·목, 하루 2교시, 1교시부터**입니다. 시작·종료 시각 대신 교시를 선택합니다. 1차시 수업은 1교시, 2~3차시 묶음 수업은 연속 2교시로 배정합니다.
- 프로젝트 2·3의 20차시를 **2026년 11월 26일 이전(11월 25일까지)**에 순서대로 배정합니다. 프로젝트 1은 기본 제외이며, 필요한 학급만 선택할 수 있습니다.
- 각 반의 **활동 완료** 차시는 건너뜁니다. 프로젝트 1을 마친 반은 **진행 체크 → P1 → 활동 완료 일괄 체크**로 반영할 수 있습니다. 각 항목의 머리글 체크박스로 선택한 반·프로젝트만 일괄 완료 또는 해제합니다. 패들렛·활동지 체크는 별도로 유지합니다.
- **기존 일정 유지**는 미배정 차시만 추가합니다. **남은 진도 다시 배정**은 선택한 반·프로젝트의 미완료 차시 중 시작일 이후 일정을 교체하고 기존 준비 메모를 보존합니다.
- 다른 수업과의 교시 충돌 및 하루 교시 수를 확인합니다. 공휴일·학교행사 등은 **수업 제외일**에 직접 입력합니다. 모든 차시를 마감 전에 배정하지 못하면 부족분을 안내하고 저장을 막습니다.
- 미리보기를 확인한 뒤 **이 일정으로 저장**하면 교체·추가 작업을 하나의 Firestore 배치로 저장합니다. 운영 일정이 동시에 바뀔 수 있으므로 저장 직전 미리보기를 확인해 주세요.

예: 2026년 10월 9일을 시작일로 두고 화·목에 2교시씩 배정하면, 완료·기존 일정·제외일이 없는 반은 프로젝트 2·3을 10월 13일에 시작해 11월 17일에 마칩니다. 연속 2교시가 필요한 묶음 수업은 같은 날짜에 배정합니다.

2026-10-09 최소 점검: 운영 및 로컬 `/api/population` HTTP 200, 최신 기준 2026-09, 캐시 지연 없음. Firestore 반 설정 조회 HTTP 200. 이후 접근 정책 변경으로 비로그인 일정·진행 기록 조회는 HTTP 403입니다. 빌드와 일정 핵심 테스트, 브라우저 미리보기를 확인했습니다. 실제 Google 로그인 후 일정 저장은 실행하지 않았습니다. 후속 수정에서 학급 설정을 1~3반으로 반영하고 Firestore 로그인 조회 규칙을 운영에 배포했습니다. 화면 수정은 로컬에서 확인합니다.

일정 등록도 수업일과 교시만 선택합니다. 완료 차시는 새 일정 목록에서 제외하며, 이미 저장된 완료 일정은 계속 조회·수정할 수 있습니다. 묶음 수업은 달력에서 하나로 표시하면서 각 차시의 진행 기록을 유지합니다. 기존 일정의 저장 형식과 보안 규칙은 유지합니다.

## 나중에 PPT와 활동지를 추가하기

### 폴더에서 추가

`추가자료` 폴더에 파일을 넣고 다음 명령으로 빌드·배포합니다.

```powershell
npm run deploy
```

파일명 `P2_11차시_인터뷰_활동지.hwpx`처럼 차시를 넣으면 자료실과 그 차시 상세 화면에 자동으로 연결됩니다. `P2_굿즈제작_참고자료.pdf`는 프로젝트 2 전체 자료로 연결됩니다. 차시가 있으면 프로젝트는 전체 차시 번호로 판단합니다. 지원 형식은 HWP/HWPX, PPT/PPTX, PDF, DOC/DOCX, XLS/XLSX, ZIP, PNG/JPG/JPEG/WebP입니다. 폴더에서 제공하는 파일은 배포된 정적 파일이므로 주소를 아는 사람도 다운로드할 수 있습니다.

### 공유 링크로 추가

관리자가 **자료 등록 → 공유 링크**를 선택해 Google Drive 등의 링크를 등록할 수 있습니다. 링크 대상의 열람 권한은 해당 서비스에서 설정합니다.

### 웹앱 파일 업로드

Dream 결제 계정에 연결된 Blaze 요금제와 서울 리전 Storage 버킷이 활성화되었습니다. 관리자는 **자료 등록 → 파일 업로드**에서 최대 50MB 파일을 올릴 수 있습니다. 로그인하지 않은 방문자도 자료실에 등록된 파일을 내려받을 수 있습니다.

Storage 보안 규칙은 검증된 관리자 Google 계정을 직접 확인합니다. Firestore 조회용 프로젝트 IAM 권한은 추가하지 않았습니다. 다운로드 CORS 출처는 이 웹앱의 `web.app`, `firebaseapp.com` 및 로컬 개발 주소입니다. 관리자 이메일을 바꿀 때는 Firestore 관리자 등록과 `storage.rules`의 계정 조건을 함께 수정해야 합니다.

## 개발과 확인

PPT 21개, 차시별 한글 활동지 22개, 공통 계획표·지도안 2개는 Firebase Storage에서 다운로드합니다. Git에는 코드·등록목록·PDF와 미리보기 이미지를 보관하며, PPT/HWP/HWPX 원본을 빌드에 포함하지 않습니다. 새 체크아웃도 원본 다운로드 없이 빌드할 수 있습니다. 파일 수정이 필요할 때만 다음 명령으로 원본을 로컬에 복원합니다. 기존 파일에 수정사항이 있으면 덮어쓰지 않습니다.

```powershell
npm run materials:restore
```

```powershell
npm install
npm run dev
npm test
npm run build
firebase deploy --only 'firestore,hosting'
```

원본을 수정하거나 새로 등록하면 `npm run materials:publish`로 Firebase CLI 로그인 계정의 권한을 사용해 업로드한 뒤 `npm run deploy`를 실행합니다. 게시 과정에서 파일 크기·MD5·공개 다운로드 내용을 확인하고, 체크섬이 들어간 별도 경로로 저장해 기존 다운로드 주소를 보존합니다. 업로드 인증 정보는 Git에 저장하지 않습니다. `scripts/prepare_curriculum.py`는 초기 프로젝트 교환용으로, `추가자료/보관`의 로컬 원본을 사용합니다. 최신 26~30차시 개정본을 재생성하는 명령은 아닙니다.

`node scripts/check-rules.cjs`는 로그인된 Firebase CLI의 인증을 사용해 Firebase 공식 Rules 테스트 API로 공개 조회, Google 로그인 편집, 관리자 업로드 접근 제어를 읽기 전용으로 검증합니다. 운영 데이터에 테스트 문서를 쓰지 않습니다. `scripts/cloud-admin.cjs status`는 인증과 결제 상태를 확인합니다. 클라이언트 Firebase 설정값은 공개 식별자이며 접근 제어는 Google 인증과 관리자 보안 규칙으로 적용합니다.

검증: 전체 차시 정렬·그룹 유지, 반별 독립 체크 집계, 일정 겹침, 링크 검증 단위 테스트; 브라우저에서 두 반 일정 등록, 독립 완료 체크, 논의 저장, 새로고침 보존, 데스크톱·모바일 화면 확인; Firebase Rules 24개 접근 제어 테스트 및 배포 시 규칙 컴파일 확인; 운영 주소의 자료 다운로드 파일 일치 검증; 원본 자료 대신 빈 ZIP 검증 파일을 이용한 Storage 공개 다운로드·CORS 검증 및 임시 파일 정리. 사용자 Google 계정으로 실제 로그인한 두 기기 사이의 공유 검증은 별도 수행하지 않았습니다.
